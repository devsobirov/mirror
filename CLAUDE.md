# mirror-workshop: CRM стекольно-зеркальной мастерской

## Назначение
Внутренняя CRM мастерской по стеклу и зеркалам (прод: xonqa-tech.uz, в работе около 2 лет).
Что умеет:
- каталог услуг с ценами и наценкой;
- заказ с калькулятором по размерам (м², периметр) и подуслугами (фацет, шлифовка, монтаж…);
- печать чека 80 мм, копирование заказа;
- дашборды выручки;
- «насия дафтар» (долги клиентов и оплаты).

## Цели
- Сейчас: продавать CRM другим мастерским. Для каждого, кто попросит, отдельно поднимается демо с чистыми демо-данными.
- В перспективе (не начато):
  - SaaS-демо с мультитенантностью;
  - каждому клиенту отдельная установка под ключ, **без SaaS- и демо-кода**, с доработками под него;
  - лендинг и заказ с сайта;
  - разделение на версии: prod, demo, feature (git-ветки).

## Стек
- PHP 8.3 (composer: ^8.2), Laravel 11.9, MySQL 8.4 (тесты: sqlite in-memory).
- Blade + Alpine.js 3 (CDN) + Tabler / Bootstrap 5 (готовые файлы в `public/build/assets`, сборки фронта нет).
- Пакеты: `laravel/ui` (auth), `maatwebsite/excel` (только склад), `opcodesio/log-viewer`; dev: `laravel/pint`, ide-helper, debugbar.

## Команды
На хосте PHP нет, всё запускается через devenv (`cd /mnt/data/projects/devenv`). Среду поднимают вручную.
```bash
./dev up / ./dev down
./dev art mirror-workshop/public_html migrate            # миграции
./dev art mirror-workshop/public_html test               # тесты (sqlite :memory:)
./dev art mirror-workshop/public_html db:seed --class="Database\Seeders\Demo\DemoSeeder"   # пересоздать демо
./dev composer mirror-workshop/public_html <args>
./dev sh   →   cd /projects/mirror-workshop/public_html && vendor/bin/pint --dirty    # линтер
```
Сайт, демо-логины, БД и бэкапы описаны в `docs/local-dev.md`.

## Конвенции
- Валидация только через FormRequest, в контроллере используется `$request->validated()`.
- Права проверяются middleware `worker` / `admin` плюс `authorize()` в FormRequest и `isAdmin()` / `isWorker()` из `HasRole`. Числа ролей в коде не сравнивать.
- Статусы и типы берутся из `app/Enums/*`, литералы `1`, `5`, `7` не писать.
- Телефон хранится как 9 цифр без `+998`. Нормализуется только через `App\Helpers\PhoneNormalizer`.
- Деньги — UZS, целые числа.
- Запись в несколько таблиц выносится в `app/Services/*` и оборачивается в `DB::transaction`.
- Имена роутов: `группа.ресурс.действие`; создание и изменение одной ручкой `save/{model?}`.
- Тексты интерфейса на узбекском (латиница). Комментарии в коде и документация на русском.
- Код по `.editorconfig` (4 пробела, LF), перед коммитом `pint --dirty`.
- Коммиты короткие, на английском в нижнем регистре, как в истории (`offer-copy fixes`).
- Правила для конкретных папок лежат в `.claude/rules/` и подгружаются сами.

## Git
- Основная ветка `main` (remote `origin`, GitHub). Перед работой создай фича-ветку от `main`. Никогда не коммить в `main`.
- Коммитишь, пушишь ветку и создаёшь PR (`gh pr create`) сам.
- Мердж и коммиты в `main` делает только владелец.

## Что нельзя ломать
- Расчёт заказа: форма, копия формы, демо-сидер и чек должны давать одинаковые суммы (эталон в `.claude/rules/offer-calc.md`).
- Формат payload `offers.save` и вход по телефону.
- Разграничение admin / worker.
- Готовые ассеты `public/build/assets/*`: исходников нет, Vite не запускать.
- Корневой `.htaccess` (rewrite в `public/`).
- Уже применённые миграции: схема меняется только новыми.
- `.env.production` не коммитить и не публиковать. Ничего не деплоить.
- Тесты только на sqlite из `phpunit.xml`. `.env`-БД `mirror` содержит демо-данные.
- Демо-данные меняются только через `database/seeders/Demo/*`, руками строки в БД не правят.
- `~/admin`: отдельный ежедневный docker-стек. Его код не читать, порты не занимать, devenv не должен его блокировать.
