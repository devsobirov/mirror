# Хостинг и деплой

## Как устроено на проде (xonqa-tech.uz)
- На shared-хостинге корень репозитория совпадает с `public_html/`.
  Корневой `.htaccess` переписывает все запросы в `public/` (`RewriteRule ^(.*)$ public/$1 [L]`), HTTPS-редирект в нём закомментирован.
  Поэтому файлы из корня (`docs/`, `CLAUDE.md`, `.env`) по HTTP не отдаются.
- `public/.htaccess` и `public/index.php` стандартные для Laravel 11.
- Готовые ассеты `public/build/assets/*` лежат в git, сборка на сервере не нужна (см. `docs/frontend.md`).
- В git также лежат `composer.phar` и `_ide_helper*.php`. `composer.lock` указан в `.gitignore`.
- Загруженные картинки (`public/assets/images/{services,goods,clients}`) в `.gitignore` и живут только на сервере.
- CI, Envoy и скриптов деплоя нет.

## Окружение
- `.env.production` в репозитории — локальная копия прод-конфига, в `.gitignore`. Не коммитить и не публиковать.
  Копия **не совпадает с продом**: в ней `APP_ENV=local`, а на проде это не так. Перед использованием её нужно сверить.
- Сейчас автоматического деплоя нет: выкладка и миграции делаются вручную. Процесс будет оформлен позже.

## План (из целей проекта)
- Деплоить через git, каждая версия в своей ветке: прод (основная мастерская), демо и разработка новых функций (feature).
- Каждому клиенту отдавать отдельную установку под ключ, без SaaS- и демо-кода.
